# 第三轮：改成「结绳本体同款 UI」之后的真机验证

反馈原话：「按结绳本体一致ui来，左右侧布局没到屏幕上下左右边，删除组件及其它功能也没有；
贴图应该是文件选择，选择assets里的资源」。

## 这一轮改了什么

| 要求 | 改法 |
|---|---|
| 按本体 UI | 设计器从 `Dialog` 换成 **`SimplePluginPage` 插件页面**（本体 `LayoutDesignerPage` 就是这种），入口用 `startPluginPage(SceneDesignerPage.class)`；页面里只有一个 `LayoutDesignerView`，没有任何自绘面板 |
| 左右栏到屏幕边 | 框架的抽屉会被「系统栏边距 + DrawerLayout 的 64dp 最小边距 + XML 里的 16dp 外边距」挤窄。页面里把两个抽屉的 `LayoutParams` 改成 `宽=屏幕宽、边距=0`，并 `drawer.setFitsSystemWindows(false)`，实例化了两次（`setContentView` 后 + `post` 一次） |
| 抽屉字看不清 | `setDarkMode(true)`——设计器那套 UI 是按深色做的，浅色主题下是白底白字 |
| 删除组件及其它功能 | 操作条照本体的五个按钮补齐：`插入代码 \| 复制代码 \| 上移 \| 下移 \| 复制 \| 删除`（层级顺序、克隆、删除都直接改模型再重建元素树） |
| 贴图 = 文件选择 | 注册 `DiverseEditor` 单独给「贴图」这个 Property 换编辑器：弹出 assets 资源列表（png 直接选，`.atlas` 展开成区域），存成 `ui/items.atlas#background` |

顺带修掉的两处：
- 页面里**返回键把整个设计器关掉**——宿主的写法是 `if (currentPage.onBack()) super.onBackPressed();`，
  所以「关抽屉」必须 `return false`，之前返回 true 等于主动退出。
- atlas 解析把 `size:` / `format:` / `filter:` / `repeat:` 也当成区域名，选到会生成坏代码，已过滤。

## 1. 属性点不动 + 闪退 ← 真因在崩溃日志里（有据可查）


也就是：点属性 → `QiBottomTextInputDialog.make(?)` 在 **inflate 阶段就抛异常**，把宿主进程带崩

- 弹窗建不起来时只 Toast + 写插件日志，**不再把宿主带崩**。

## 三个问题的真因

| 现象 | 根因(有据) |
|---|---|
| 属性点不动 / 一改属性就崩 | `Crashes/crash-2026-10-14-00-58-15.log`:`layout/dialog_bottom_input` 第 99 行的 `QiButton`(MaterialButton) 校验主题 `The style on this component requires your app theme to be Theme.MaterialComponents`。插件页跑在 `SimplePluginActivity`,manifest 主题是 `Theme.AppCompat.Light`(非 Material);本体不崩是因为它跑在 `TieAppLayoutDesign`(application 主题 `AppTheme→QiUI→Theme.MaterialComponents.*`) |

| 精灵选了贴图没预览 | `SceneElementView.onDraw` 只画色块 + 文字,根本没解码/绘制贴图 |

## 改了什么

1. **`UiContext.java`(新增)**:把当前 Context 用宿主 application 主题(`ContextThemeWrapper`)包一层再交给 `QiBottomTextInputDialog`,满足 Material 主题校验。

3. **`AssetPicker.java`(重写)**:默认直接列工程 `assets/` 资源 —— 子目录可点进入、有「⬆ 上一级」、png/jpg/jpeg/webp 直接选、`.atlas` 展开成区域;底部「浏览其它文件...」才走宿主文件选择器。

7. **`SceneCanvasView.sync()`**:换贴图后显式 `child.invalidate()`(硬件加速下子 View 复用显示列表,不刷新看不到变化)。
8. **属性按组件类型区分**(`SceneElementProvider`):只有标签/文本按钮有「文本」,只有图片/精灵有「贴图」,演员/表格/组不再显示改了不生效的迷惑项。

## 1. 插入代码不再自动加 @附加资源
`CodeMerge` 删掉了 `ensureAssetAnnotation`:不再往文件头塞 `@附加资源("../../assets")`。
需要该注解的文件由用户自己维护,插件只负责把生成代码灌进同名类。

## 2. 可视化编辑后自动写回当前 .t,重入可继续编辑
- 新增 `SceneStore`:读/写目标 `.t`(文件正被宿主编辑器打开时用 `editor.setText` 同步,否则直接写盘);
  读写 `<文件>.scene.json`(舞台尺寸 + 元素快照 + 类名)。
- `SceneDesignerPage`:
  - `prepare(...)` 增加目标文件路径参数;
  - 记录 `dirty`(`SceneModelHolder` 新增 `ModelChangedListener`,任何加/删/改属性/拖动都置脏);
  - `onBack()` / `onDestroy()` 退出时 `autoSave(false)`:**有改动才写**,同名类整块替换、否则追加;
  - 「插入代码」按钮改为强制写回目标文件(`autoSave(true)`);
  - 三个菜单入口(代码长按 / 工程菜单 / 文件树)都传目标路径,打开时用 `SceneStore.loadModel`
    优先从 `.scene.json` + 代码文本回读。

## 3. 安全护栏(关键)
从 `小鸡顶篮球.t` 进入编辑器时,文件名派生的类名 `小鸡顶篮球` 会命中用户的
`类 小鸡顶篮球 : 游戏类`,直接整块替换会把用户的游戏类抹掉。`CodeMerge` 新增:
- `isSceneClass(text,name)`:该类是否以「变量 舞台:舞台?」为标志(即本编辑器生成的场景类);
- `uniqueClassName(text,base)`:取不重名的 `base`、`base2`、`base3`...;
- `resolveSceneClassName(text,base)`:无同名类→用它;同名且是场景类→覆盖它;
  同名但对不上(用户的游戏类)→换成 `base场景`(已存在同名场景类则复用它)。

## 4. 文件树「新建文件 → 新建场景类」
- 新增 `NewSceneClassOption implements PSObjectCreationOption`(参考 `scala安卓工程插件` 的
  `ScalaCreationOption`/`ScalaClassCreationOption`):宿主「新建文件」有多个创建方式时会弹
  「选择方式」列表,选中「新建场景类」再弹「输入类名」表单,确定即生成 `<类名>.t`(空场景类骨架:
  舞台 / 创建场景 / 绘制场景 / 触摸)并写好 `<类名>.t.scene.json`。
- `program.json` 注册扩展点 `project.file.creationOption`,`scope = {unit:project, identifier:"cn.tiecode.android"}`
  (只对结绳安卓工程生效),版本升到 1.1。

# 第七轮:资源根目录同时识别 `assets/` 与 `资源/`

反馈:「/storage/emulated/0/Tiecode/Projects/我的游戏/资源/ 贴图默认没弹出这个文件选择器,选择不了这个文件夹」。

## 真因
插件只把工程里的 `assets/` 当资源根目录(`ProjectAssets.dir()`),而「我的游戏」这个工程的
资源目录叫 **`资源/`**,于是 `dir()` 返回 null —— 「贴图」属性只能退回宿主系统文件选择器
(起始在公共根目录),根本进不到工程资源目录。

实测本机工程命名并不统一:`接球小游戏`→`assets`,`我的游戏`/`蓝莓修仙`/`spine动画`→`资源`。

## 改了什么
`ProjectAssets`:资源根目录改为按候选名查找 `{"assets", "资源", "Assets"}`,
先问宿主当前工程目录,再从未编辑文件所在目录逐级向上找(最多 6 级)。

## 验证(离线)
把目录识别逻辑抽成独立片段编译运行:

- `我的游戏/源代码/我的游戏场景.t` → `.../我的游戏/资源`
- `蓝莓修仙/源代码/*.t` → `.../蓝莓修仙/资源`
- 无资源工程 → `null`(仍退回系统文件选择器)
